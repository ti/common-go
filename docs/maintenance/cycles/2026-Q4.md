## 3. Work breakdown

**W0. Review (Day 1, no production code changes).** Walk every area in playbook §3.3. Turn each §2.2 hypothesis into a failing test on a review branch. Read the upstream release notes. Update §2 with the results and get sign-off.

**W1. Safety net.** Track `go.sum` and fix `.gitignore`. Add `.golangci.yml` (codifying the rules applied in commit 5f7b05b) and `.github/workflows/ci.yml` (vet, race tests, golangci-lint, govulncheck, examples build, CJK check). Add the subprocess SIGTERM test and the bridge conformance tests.

**W2. Security and dependency upgrade (S1).** Set Go to 1.27.3 (CI/toolchain), then `go get -u` the direct dependencies and `go mod tidy`, in its own commit. govulncheck must be clean.

**W3. Lifecycle (B1, B2).** Rewrite `graceful.Start` around `signal.NotifyContext`, registering the signal **before** the servers start and dropping the goroutine-ID hack. Use a mutex-guarded LIFO closer registry with one overall deadline (`GRACEFUL_TIMEOUT`, default 60s). `Server.Close` order: NOT_SERVING → `PRE_STOP` → HTTP Shutdown and gRPC GracefulStop in parallel → closers. `async`: add `Future.Go(func(ctx) error)` for the `struct{}` case, leaving `Async[I,O]` unchanged.

**W4. Network layer (B3–B7, N1–N5).**
- HTTP server: stdlib-only HTTP/2 (`Protocols` + `HTTP2Config`) and drop `x/net/http2` from the server path. Make timeouts and limits configurable, with the same defaults, and keep Read/Write timeouts at 0 for streaming.
- gRPC server: `WithKeepalive(...)` with defaults `MaxConnectionAge 1m` (kept), `Grace 30s`, `EnforcementPolicy{MinTime 10s, PermitWithoutStream true}`. Register user services on `bufServer` too.
- Connect/auto-HTTP: dispatch through `grpc.MethodDesc.Handler(srv, ctx, dec, interceptor)` with no per-request reflection. Add opt-in `WithHTTPInterceptors()`, which applies validator, recovery, metrics and authz (auth is excluded because the HTTP middleware already does it). Add gzip, `Connect-Timeout-Ms`, a protocol-version check, GET for `NO_SIDE_EFFECTS`, a configurable body limit and error details. Implement the `WithConnectOptions` stub.
- gRPC client: new additive query parameters `keepalive=`, `waitForReady=`, `retryPolicy=native`.
- HTTP client: give each client a cloned, tuned transport (`MaxIdleConnsPerHost` 64, `IdleConnTimeout` 90s, `ForceAttemptHTTP2`, new parameters `maxIdlePerHost`, `idleTimeout`, `h2c`). Fix the tracing order. Cache one transport per proxy URL. Retry with jittered backoff, only for idempotent methods by default (`retryNonIdempotent=true` opts in), and retry on 502/503/504.

## 5. Behavior changes (→ `docs/upgrades/2026-Q4.md`)
1. Graceful shutdown starts working. `PRE_STOP` is honored, and the pod must have `terminationGracePeriodSeconds` > `PRE_STOP` + drain.
2. `?proxy=` no longer leaks into other HTTP clients.
3. `?tracing=true` HTTP clients emit spans.
4. HTTP client retries back off and skip non-idempotent methods by default.
5. The gRPC server tolerates client keepalive pings, and gRPC clients send keepalives by default.
6. `WithHTTPInterceptors()` is opt-in this cycle. The plan is to make it the default in 2027-Q1 once auth runs with it.
