# Upgrading to the 2026-Q4 release

This guide is for services that depend on `github.com/ti/common-go` and are moving from any earlier commit to the 2026-Q4 modernization. Follow it top to bottom: the sections are ordered by priority.

- Sections 1–3: every service should apply them.
- Section 4: features to adopt when you touch the code.
- Section 5: verification.
- Section 6: a worked example (`auth`).

The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md). The reasoning and evidence behind each change are in [docs/maintenance/cycles/2026-Q4.md](../maintenance/cycles/2026-Q4.md).

**Why upgrade now:** the previous versions had two production problems. First, **graceful shutdown never ran**: SIGTERM killed the process immediately, so every rolling update dropped in-flight requests even when `PRE_STOP` was configured. Second, the dependency set had **10 vulnerabilities reachable from your code** (grpc, x/net, x/text, crypto/x509).

---

## 1. Bump the dependency

```bash
# Go 1.27.3 or newer (the library pins toolchain go1.27.3; stdlib security fixes)
go get github.com/ti/common-go@<commit-or-tag>
go mod tidy
go build ./... && go vet ./... && go test ./...
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

Your `go.mod` must say `go 1.27` or newer (the library uses Go 1.27 generic methods). Projects still on Go 1.26 first need `go mod edit -go=1.27` and a 1.27 toolchain.

This moves your build to grpc v1.85, grpc-gateway v2.33, x/net v0.62, OpenTelemetry v1.47 (contrib v0.72), mongo-driver v2.9.3, sarama v1.61 and connect-go **v2**. `connectrpc.com/connect` v1 is no longer pulled in by common-go.

If you verify against a local checkout, use a temporary copy of your `go.mod` with a `replace` (see [playbook §3.8](../maintenance/playbook.md)). **Do not use a `go.work`.** Workspace mode merges unpruned module graphs and reports a false `ambiguous import` for the old monolithic `google.golang.org/genproto`.

## 2. Breaking changes (fix these or the build/behavior changes)

| # | Change | What to do |
|---|---|---|
| B1 | `grpcmux.WithConnectOptions` (connect-go v1 handler options) is **removed**. | Generate connect-go **v2** code and register it with `pbconnect.RegisterXxxHandler(gs.ConnectServer(), impl)`. connect-go ships a rewrite tool: `go install connectrpc.com/connect/v2/cmd/connect-go-v2-migrate@latest && connect-go-v2-migrate -w && buf generate && connect-go-v2-migrate -w`. v1 handlers can still be mounted with `RegisterConnectHandler(gs, path, h)`, but they won't run the grpcmux interceptor chain. Services that only use `RegisterConnectService` need no change. |
| B2 | **The gRPC interceptor chain now runs on the HTTP bridges by default.** That covers `RegisterConnectService`, `WithAutoHTTP` routes and `gs.ConnectServer()` handlers, and the chain includes validation, authz policy, metrics, rate limiter, your `WithGRPCUnaryServerInterceptor` interceptors and recovery. | Requests that previously skipped validation over Connect/HTTP are now validated, which is the intended outcome. Check that your custom unary interceptors don't assume a real gRPC transport: they get a `grpc.ServerTransportStream` (`grpc.Method`, `SetHeader`, `SetTrailer` work) and a `peer.Peer` from the HTTP remote address, but no TLS `AuthInfo`. To restore the old behavior temporarily, use `grpcmux.WithoutHTTPInterceptors()` or `apis.disableHTTPInterceptors: true`. Authentication and access logging are **not** run twice; the HTTP middleware still does them. |
| B3 | **gRPC client TLS rule.** TLS is now used only for `secure=true`, `https://` or `grpcs://`. Previously any scheme *ending in "s"* meant TLS, including `dns://`. | `dns://host:port` is now plaintext, which is what the docs always described and what grpcmux servers expect. If you relied on the implied TLS, add `?secure=true`. `dns:///host:port` (three slashes) and `unix:///path` targets now work. |
| B4 | `graceful.Start` now actually waits for SIGINT/SIGTERM, from any goroutine, and **returns** after shutdown. It also shuts down when one of its functions returns an error (for example, a port already in use). Closers share one deadline, `GRACEFUL_TIMEOUT` (default 6m). | Code after `gs.Start()` in `main` now runs at exit, so keep it short or remove it. Make sure Kubernetes `terminationGracePeriodSeconds` > `PRE_STOP` + your longest request (section 3). |
| B5 | `PRE_STOP` parsing: `0`/`0s` now means **no wait** (it meant 1 minute). Values over 5m are capped at 5m (they meant 1 minute). Unset still means no wait; unparsable still means 1 minute. | Only matters if you set `PRE_STOP=0` or more than 5 minutes. |
| B6 | `dependencies/http` retries: `try=N` now retries with exponential backoff and jitter (`backoff=`, default 100ms). Non-idempotent methods (POST, PATCH) are retried only after dial errors, with an `Idempotency-Key` header, or with `retryNonIdempotent=true`. 502/503/504 responses are retried for safe requests. Before, every error was retried immediately, POST included, and 5xx never. | If a POST endpoint relied on blind retries, send an `Idempotency-Key` or add `retryNonIdempotent=true` to the URI. |
| B7 | `dependencies/http` no longer shares or mutates `http.DefaultTransport`. Each client owns a tuned transport (64 idle connections per host), `?proxy=` affects only that client, and a client passed with `WithHTTPClient` is copied, never modified. `?tracing=true` now really wraps the transport. | If you set a proxy on one client and (unknowingly) relied on it for others, give those clients their own `?proxy=`. `WithHTTPClient(&http.Client{})` now opts **out** of the tuned transport; drop it unless you need a custom transport. |
| B8 | JSON for **your** types (HTTP client bodies, `mqlru` values, SQL JSON params, Mongo page results, `mongo/codecs`) is back to `encoding/json` v1 semantics: case-insensitive field matching, nil slices as `null`. The previous commit (c9386fc) had switched them to json/v2 defaults, which silently left case-mismatched fields of third-party responses empty. | Revert any workaround you added for the json/v2 behavior. |
| B9 | The mock database returns errors that carry gRPC codes (`NOT_FOUND`, `ALREADY_EXISTS`, ...), like the SQL and Mongo backends. | Tests that expected `codes.Unknown` from the mock now see the real code. Use `database.IsNotFound(err)` / `database.IsAlreadyExists(err)` instead of backend-specific checks. |
| B10 | Mock `FindRows` rows now decode to the type passed as `oneData` (`*T`), like SQL and Mongo. They used to return a raw `map[string]any`. | Remove any `map[string]any` handling written for the mock. |
| B11 | REST error responses no longer copy raw gRPC trailers into HTTP headers. Before, `Grpc-Trailer-Grpc-Status-Details-Bin` carried binary data that HTTP/1.1 clients reject as malformed. That happened with gateways registered on a gRPC connection (`RegisterXxxHandlerClient`/`RegisterXxxHandler`) whenever the error had details. `x-*` metadata is still forwarded. | Nothing, unless a client read `Grpc-Trailer-*` headers. |
| B12 | `dependencies/http` metrics: the `http_path` label no longer includes the query string. | Update dashboards or alerts that matched on query strings. |
| B13 | Upstream behavior: grpc-gateway v2.32 **rejects duplicate query parameters** for non-repeated fields (`?a=1&a=2` → 400). grpc v1.82 made load-balancing policy names case-sensitive. grpc plans to lower the default max header list size to 8 KB, so watch large cookies/JWTs that are forwarded as metadata. | Check clients that repeat query parameters. Use lower-case LB names (`round_robin`). |

## 3. Kubernetes: make the drain work

The drain now happens, so configure it:

```yaml
terminationGracePeriodSeconds: 60      # > PRE_STOP + longest request
env:
  - { name: PRE_STOP, value: "10s" }   # time for endpoints/LBs to stop routing to the pod
readinessProbe: { grpc: { port: 8081 } }          # or httpGet /readyz on :8080
livenessProbe:  { httpGet: { path: /healthz, port: 8080 } }
```

- `/healthz` is liveness. It always returns 200 while the process serves HTTP, so a failing dependency never makes Kubernetes restart the pod.
- **New `/readyz`**: readiness, the same state as gRPC health. It returns 503 before the gRPC listener is up, from the first moment of shutdown, and whenever a checker added with `gs.AddHealthChecker` fails. Point load-balancer health checks (Envoy, ALB) at `/readyz`, not `/healthz`.
- A complete manifest is in [examples/deploy/k8s/deployment.yaml](../../examples/deploy/k8s/deployment.yaml).

## 4. Recommended adoption (new capabilities)

1. **protovalidate.** `buf.validate` annotations are enforced on every protocol automatically; protoc-gen-validate's generated `Validate()` methods keep working. Move protos from `validate/validate.proto` (deprecated) to `buf/validate/validate.proto`. Field rules should use `ignore = IGNORE_IF_ZERO_VALUE` where partial updates send empty fields; put "required on create" in a message-level CEL rule (see `examples/proto`).
2. **Delete hand-written `req.Validate()` calls** in handlers once B2 is in place. Validation now happens before the handler on gRPC, Connect and auto-HTTP. grpc-gateway `RegisterXxxHandlerServer` routes still call the handler directly; see item 3 for how to cover them.
3. **REST with interceptors and streaming.** Register the gateway on the in-memory connection, `pb.RegisterXxxHandlerClient(ctx, gs.ServeMux(), pb.NewXxxClient(gs.Conn()))`, instead of `RegisterXxxHandlerServer`. REST requests then run the full gRPC chain (including validation) and support server streaming (newline-delimited JSON). `gs.Conn()` now reaches every registered service; before, it reached only health.
4. **connect-go v2 for streaming and gRPC-Web** (`gs.ConnectServer()`; see [connectrpc.md](../guides/connectrpc.md)). Handlers may keep returning gRPC status errors; grpcmux converts them to `*connect.Error`.
5. **Errors in AIP-193 style:** a canonical code plus `google.rpc.ErrorInfo{reason, domain, metadata}`. Details now reach Connect clients, alongside REST and gRPC. `mux.RegisterErrorCodes` custom codes keep working on the Connect bridge.
6. **Connect bridge features**, available without code changes: gzip in both directions, `Connect-Timeout-Ms` deadlines, GET for methods with `option idempotency_level = NO_SIDE_EFFECTS`, error details, and `grpc.SetHeader`/`SetTrailer` metadata. The body limit defaults to 32 MiB (`WithMaxRequestBodyBytes` / `apis.maxRequestBodyBytes`).
7. **gRPC client URI options:** `keepalive=30s` (connections through NAT/LB), `waitForReady=true`, and `retryPolicy=native` (gRPC's built-in retry with backoff for UNAVAILABLE).
8. **Server options:** `WithHTTPTimeouts`, `WithMaxConcurrentStreams`, and `WithKeepalive`. The default enforcement policy now accepts client pings every 10s; gRPC's own default sends GOAWAY `too_many_pings` at intervals under 5 minutes.
9. **HTTP client URI options:** `maxIdlePerHost=`, `idleTimeout=`, `h2c=true`, `backoff=`, `retryNonIdempotent=true`. Per-request `WithProxy(ctx, url)` now reuses one pooled transport per proxy.
10. **`async.Future.Go(func(ctx) error)`** for fan-out without results.
11. **`database.IsNotFound` / `IsAlreadyExists`** for backend-independent error handling.
12. **Logging:** `log.Fatal` now writes a structured JSON line with the logger's fields before exiting. Messages are printf-style format strings; pass fields with `log.With(map[string]any{...})`, not as key/value arguments.

## 5. Verify

```bash
go build ./... && go vet ./... && go test -race ./...
golangci-lint run ./...                                     # v2; see common-go's .golangci.yml
go run golang.org/x/vuln/cmd/govulncheck@latest ./...       # expect: no vulnerabilities
```

Then run a smoke test on every protocol you serve: native gRPC, REST, and Connect (JSON and binary). The [examples integration test](../../examples/internal/app/app_test.go) shows how to start the real server on free ports and call it.

After deploying, run one rolling update under load and confirm that there are no 5xx/`UNAVAILABLE` spikes during it, and that the pod logs show `graceful.Shutdown` followed by a clean exit, not exit code 143.

## 6. Worked example: `auth/backend`

`~/Workspace/projects/auth/backend` (module `github.com/ti/authentication`) is the reference consumer. A temporary `go.mod` with a `replace` to this release tidies, builds, vets and passes `go test ./...` **with no code changes**. Recommended follow-ups, in order:

1. **Bump** `github.com/ti/common-go` (section 1). `connectrpc.com/connect v1.20.0 // indirect` disappears from `go.mod`.
2. **Charts.** `PRE_STOP=10s` with `terminationGracePeriodSeconds: 60` is already correct, and now takes effect for the first time. The comments in `charts/values.yaml`, `templates/backend.yaml` and `templates/idaas.yaml` describe the drain as working before this release; update them. Point the Envoy/ALB health check at `/readyz`. The liveness probe on `/healthz` is right as is.
3. **Validation.** The 25 hand-written `req.Validate()` calls in handlers served through `RegisterConnectService` (27 services) are now redundant: the validator runs first. Remove them after the upgrade, keeping any that run on `RegisterXxxHandlerServer`-only REST paths, or move those routes to the `gs.Conn()` gateway (section 4.3).
4. **Database errors.** `preserveDBStatus` / `isNotFound` in `internal/auth/dberror.go` exist because some storage errors had no gRPC code. The mock now returns coded errors and `database.IsNotFound` covers every backend, so those helpers can be simplified. Tests on the mock may now see `NotFound` where they saw `Internal`.
5. **HTTP clients.** `tools/provider/**` uses `dephttp.WithProxy` for OAuth providers; it now reuses pooled connections, with no change needed. `dependencies/sms/sms.go` passes `WithHTTPClient(&http.Client{})`. Drop that option to get the tuned transport, or keep it and accept `http.DefaultTransport`'s settings (the client is copied, not mutated).
6. **Plugin gRPC clients** (`internal/auth/service.go`, `grpcmux.NewClient(ctx, pluginAddr, ...)`). If a configured plugin address uses `dns://` against a TLS endpoint, add `?secure=true` (B3). Consider `&waitForReady=true&keepalive=30s` for long-lived plugin connections.
7. **Error codes.** `mux.RegisterErrorCodes` (5 call sites) keeps working on the Connect bridge. New errors should prefer canonical codes plus `ErrorInfo` reasons (section 4.5).
